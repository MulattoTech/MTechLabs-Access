# Engineering tool metadata accuracy review

Scope: Read-only static review of the 28 descriptors in `integrations/mcp-manager/lib/engineering-tools.mjs`, their math/infrastructure/code providers, job runner, toolkit configuration, command runner, math worker, gateway admission and policy. No repository edits, provider execution, package installation, upstream process launch, credentials, runtime/production changes or broad tests. Proposed descriptions are in the adjacent JSON mapping; they are plain text with literal newline-separated labels and no reliance on Markdown rendering.

## Metadata corrections that matter

1. Patch preview remains write-gated. `engineering-tools.mjs` declares `mterm_patch_apply_checked` with readOnlyHint=false and maps it to `repoWrite` regardless of `apply`. `policy.mjs` excludes it from READ_ONLY_TOOLS, so managed gateway calls require enabled, writable global policy even for apply=false. `checkedPatch` only checks HEAD once; checking and applying are separate Git commands, not an atomic transaction.
2. The checkpoint provider does not enforce production checkpoints. `infrastructure.mjs` calls `Checkpoint-VM` without selecting/verifying checkpoint type. It first requires attached disks and at least 10 GiB measurable free space on each drive derived from each disk path. The existing word “production” overstates the code. Manager resource admission also applies.
3. Shutdown is an actual command request, not a verified success guarantee. The exact invocation is `Stop-VM -Name ... -Shutdown -Passthru`; no force/turn-off flags are supplied. Target-host parameter support was not executed or independently verified. Descriptions state the invocation instead of promising graceful completion.
4. Repo inspection excludes untracked files from both `clean` and `modifiedFiles` because it runs `git status --short -uno`. Package scripts are only represented by names with a `<defined>` marker; up to 50 names are returned. Manifest discovery filters at most 100 directory entries.
5. Repository relative paths select a repository, not arbitrary scoped subdirectories. `allowedRepository` confines the real path to a configured root; `codeOperation` then requires it to equal `git rev-parse --show-toplevel` (comparison lowercases both paths). For direct code tools relativePath defaults to `.`. Repository job submissions require an explicit string relativePath, despite its optional/default wording in the advertised shared schema.
6. Code diagnostics execute Git and `node --check`, not package/application modules. They cover whitespace plus at most 25 changed tracked .js/.mjs/.cjs files relative to HEAD, with no TypeScript typechecking or compiler semantic analysis. Untracked files are excluded, and deleted or outside-resolving files produce per-file failures. Aggregate results can exceed the wrapper's 48,000-character ceiling and be rejected.
7. `mterm_code_symbols` is a regex heuristic for declaration keywords. `mterm_code_references` is fixed-string substring matching, including comments, strings and longer identifiers. Neither performs semantic resolution. Both retain at most 150 lines after bounded capture. Their `truncated` flag reports command capture truncation, not the separate 150-line slice. The accepted `$` identifier character is interpolated into the declaration regex without escaping, so declaration searches containing it may be surprising; no behavior change is proposed.
8. `mterm_test_run` always requires testRun and writable policy, including git-diff-check. npm-lint uses `npm run lint --if-present`, so a missing lint script can pass. Test/npm commands execute repository code and may change files. The direct child is killed at timeout, without guaranteed descendant termination. Its direct call does not independently require codeRead; repository test job submission does.
9. Job status/logs bypass only the jobs capability check. They still need enabled managed policy and supported authentication/bridge admission; both are permitted under read-only policy. Their database helper may create the state directory, SQLite database/WAL and schema even though the MCP annotations remain read-only. These existing annotations and gates must remain unchanged.
10. Job submission permission checks differ by kind: vm_inventory requires vmRead; repository kinds require codeRead; run_tests additionally requires testRun and an allowlisted command. Repository resource checks happen when the runner executes. Submission is blocked at 100 waiting records or 1,000 total retained records; resumption does not repeat those queue/history limits.
11. Queued cancellation immediately sets cancelled; running cancellation only records a request. The runner polls every two seconds and aborts its controller; aborted running work finishes as interrupted with an uncertainty error, not cancelled. Descendant processes may survive. vm_inventory calls vmOperation without an abort signal, so its command itself is not interrupted by this controller.
12. Resume accepts failed, interrupted and cancelled, requires confirm=true, and permits at most three requeues. It clears old result/error/timestamps/cancellation state and reuses original arguments from the beginning. It is not process checkpoint continuation. `resumeJob` does not repeat submitJob's per-kind capability checks; the runner's launch gate rechecks jobs plus global enabled/writable policy, and repository execution rechecks root allowance/resource conditions. Avoid claims that every original capability is revalidated on resume.
13. Missing job-status and job-logs behavior differs. jobStatus returns undefined for an absent row, causing the engineering wrapper to fail on serialized.length; jobLogs deliberately returns null and the wrapper can serialize it. The descriptions do not promise null for job status.
14. Large job results are replaced by a small truncation object when their serialized form exceeds 48,000 characters. The outer engineering response has the same limit, so wrapper overhead may reject a near-limit stored result. The provider's note that “the full result remains local” does not identify durable storage; no description promises retrievable complete logs. Resuming deletes previous stored result evidence.
15. Math equivalence is `simplify(left-right) == 0`. False is not a general proof of inequivalence, and the interface has no assumptions/domain specification. Math evaluation strings are each sliced at 2,000 characters. Solve retains at most 32 roots of at most 500 characters each, subject to the smaller 6,000-character worker-output cap. Unit arithmetic uses Decimal precision 60 and is limited to the enumerated same-dimension units.
16. Inventory does not include CPU model: base fields are OS/architecture, logical CPU count and memory. Windows GPU/volume details are best effort and may be null. VM disk “health” only reports virtual-disk metadata, not integrity/SMART health or host free-space checks. Docker/WSL return raw bounded command output, not a normalized container/distribution object schema.

## Common implementation limits

- `executeEngineeringTool` rejects unsupported keys and missing required keys, then dispatches provider validation. It does not itself perform complete JSON Schema type/range validation. Descriptions reflect declared input constraints and relevant provider checks without claiming schema validation is universally enforced.
- Global policy applies in gateway admission before engineering dispatch. Calling provider or execution helpers directly is not equivalent to passing through managed admission. All proposed permission lines describe the managed MCP surface.
- `runCommand` spawns one executable with an argument vector and shell=false. It merges stdout/stderr, caps a JavaScript string by character count, and kills only the immediate process on timeout/abort. Limits are described as characters, not bytes. Math Python input additionally has a 4,096-byte read limit.
- All engineering success results are serialized into a single text content block. The wrapper rejects serialized results longer than 48,000 JavaScript string characters. Errors have isError=true and bounded text.
- No claim is made that metadata has been deployed, seen by ChatGPT, or rendered correctly in settings/UI. This is a source metadata proposal only.
