## Source

[read-only-preflight.ps1](read-only-preflight.ps1) is intentionally pinned to the documented owner-host paths and the existing, private nine-object ACL baseline. The baseline's *SHA-256 digest* is in source, **not the baseline's raw SDDL or account identifiers**. The private baseline is retained locally under:

`%LOCALAPPDATA%\MTechLabs\MTermEngineering\Issue46\acl-baseline-20261120.json`

There is no automatic ACL backup, restore, install, account creation, mutation or elevation behavior. This script reads that baseline **once into a bounded byte snapshot (maximum 64 KiB)**, verifies SHA-256 of those same bytes, strictly decodes UTF-8, and then compares current ACL SDDL strings, filesystem object types (file versus directory), and reparse-point flags. It does not separately reopen the file to parse it after hashing; it never prints raw security descriptors, SIDs, owner names, account/profile paths, process command lines or token/credential contents. It checks eleven declared paths, including candidate directory names that currently do not exist. The candidate roots are *proposals*, not allocated or validated locations. Any candidate root that unexpectedly exists is explicitly `candidate-root-unqualified:<id>` until separately approved provisioning and real account/ACL/namespace verification. Reparse points, broad or unclassified mutation grants, and unreadable candidate roots generate additional blockers; absence is an observation, not future ownership assurance.

## Invocation

Run under the owner's existing ordinary Windows context using PowerShell **7 or later**:

```powershell
pwsh -NoLogo -NoProfile -NonInteractive -File .\read-only-preflight.ps1
```

The output is one JSON diagnostic document. The DEV listener must be absent before provisioning; an unexpectedly occupied or unverifiable DEV port is a blocker. An observed reference-manager directory is always *unqualified* until separately verified under its real Windows identities, irrespective of appearance or owner-reported ACLs. Production port `19740` must have exactly one listener across **all IPv4 and IPv6 addresses**, bound to `127.0.0.1`; an additional wildcard, IPv6 or duplicate loopback listener produces `production-listener-nonexclusive` (the script does not establish process/source identity). After reading the owning process, the script performs a **second read-only socket inventory** and requires the same one-and-only `127.0.0.1:19740` binding and owning PID. `listeners.productionSocketRecheck` reports `matched`, `changed` or `not-run`; mismatch generates `production-owner-binding-drift` and leaves the invocation unverified. A second match narrows the sampling gap but does not prevent subsequent process transitions or prove immutable file identity. Once the sole loopback listener is confirmed, `listeners.productionInvocation` reports `invocation-fields-match` only when its owning PID resolves to the expected Node executable, manager entry argument, and a single `--config` argument paired with the expected state path. Mismatch or inaccessible process evidence generates `production-invocation-mismatch` or `production-invocation-unverified`. This **does not** attest loaded source, trust in the process token, or the absence of other malicious arguments. A report with `baseline.status="matched"`, `startup="configured-exact"`, and `listeners.production="listener-present"` means *those particular read-only observations* passed; **it is not an approval ticket**. `activationAuthorized`, `provisioned` and `readyForDevActivation` remain `false` regardless of readings. The script does not test under the absent `MTermDev` token and cannot attest current running source, same-ACL/same-type object replacement, hardlink aliases, alternate links or namespace races, OS-enforced isolation, Cloudflare or connector grants. Matching attributes are **point-in-time observations, not immutable object-identity attestation**.

A mismatch, inaccessible ACL or path lookup, denied account query, missing or nonlocal baseline location, unexpected startup shortcut or absent production listener is reported as a blocker or unverified observation; the tool does not auto-repair or retry. The private-baseline digest pins only one collected snapshot, not future legitimate changes; any later approved change requires a fresh owner-reviewed baseline and controlled rollout.
